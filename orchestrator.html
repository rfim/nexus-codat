One Python graph, from feed to fix.

Every step is a Dagster asset; every contract is checked twice, as SQL and as a Great Expectations suite; and when a check fails, an on-call agent connects to the MCP server, investigates with read-only tools, and files an incident with a proposed fix. This is the record of the last run.

01 · Asset checksdagster.AssetCheckResult

Every rule, checked on every run.

Pipeline checks (replay, quarantine, idempotent re-run) sit on their layers. Each Insights product carries two: the SQL checks compiled from its contract, and a Great Expectations suite generated from the same YAML.

02 · Great Expectationssrc/nexus/quality_gx.py

The contract, as expectations.

One YAML contract becomes one ExpectationSuite: not-null, accepted values, ranges, grain uniqueness, row count and the grain columns. GX owns the column rules; the SQL checks keep what one table can't say (reconciliation to source, consent).

def suite_for(c: dict) -> gx.ExpectationSuite:
    suite = gx.ExpectationSuite(name=f"{c['product']}__contract")
    E = gx.expectations
    for col in c.get("columns", []):
        for test in col.get("tests", []):
            name, arg = ...
            if name == "not_null":
                suite.add_expectation(E.ExpectColumnValuesToNotBeNull(column=col["name"]))
            elif name == "accepted_values":
                suite.add_expectation(E.ExpectColumnValuesToBeInSet(column=..., value_set=list(arg)))
            elif name == "range":
                suite.add_expectation(E.ExpectColumnValuesToBeBetween(column=..., min_value=..., max_value=...))
    suite.add_expectation(E.ExpectCompoundColumnsToBeUnique(column_list=list(c["grain"])))
    suite.add_expectation(E.ExpectTableRowCountToBeBetween(min_value=1))
    return suite
03 · The on-call agentClaude · MCP client over stdio · read-only tools

A check failed. The agent investigates.

The incident_report asset starts the real nexus-insights MCP server as the on-call identity, lists its tools, and runs the investigation. With credentials it is Claude (claude-opus-5-5, adaptive thinking, effort high); without, the same MCP calls run in a fixed order with simple rules, labelled as such.

async def diagnose_with_claude(session, client, transcript):
    listed = await session.list_tools()                     # the MCP server's read-only tools
    tools = [{"name": t.name, "description": t.description, "input_schema": t.input_schema} for t in listed.tools]
    tools.append(REPORT_TOOL)                                   # submit_incident_report, strict schema
    for _ in range(MAX_TURNS):
        resp = await client.beta.messages.create(
            model="claude-opus-5-5", max_tokens=16000, system=SYSTEM, tools=tools, messages=messages,
            output_config={"effort": "high"},
            betas=["server-side-fallback-2026-07-01"], fallbacks="default")
        if resp.stop_reason == "refusal": raise RuntimeError(...)
        messages.append({"role": "assistant", "content": resp.content})
        for call in [b for b in resp.content if b.type == "tool_use"]:
            if call.name == "submit_incident_report": report = call.input
            else: out = await session.call_tool(call.name, dict(call.input))   # through MCP
        messages.append({"role": "user", "content": results})        # all results of a turn together
